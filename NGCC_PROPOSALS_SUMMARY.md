# NGCC proposal integration and test results

This document lists call names, source provenance, sizes, and verification status for each parameter set. Build instructions are in [README](README.md); API and command-line usage are in [Usage](USAGE.md).

Snapshot date: **2026-10-21**. Total: **74 schemes, 228 parameter sets**; **220 integrated** (71 schemes, 109 KEM, 111 signatures), **8 not integrated**. Results apply to the modules identified in “Test and source snapshots” and to the test environments below. Submitted reference implementations remain byte-identical (`author_source_edits: false`); outer adaptation is in `make/schemes/` and `make/compat/`.

The integration scope is the proposals’ reference implementations (ref). It does not include withdrawn Tins, 384/512-bit security categories, SHAKE variants, or optimized implementations. Dimensions such as 512 or 1024 in parameter names are not security strengths; see the tables for the security category. Public security reports are cited separately and are not used as the criterion for functional-availability marks.

## Test platforms

### mac (macOS ARM64)

- **OS**: macOS 26.6.2.
- **Compiler**: Apple clang 15.0.0 (`clang-1500.3.9.4`); macOS SDK 14.4.
- **Provider build configuration**: target `darwin64-arm64-cc`, `-arch arm64`, default `CFLAGS=-O2`.
- **Test host**: Tongsuo 8.5.0-pre1. TLS signatures depend on the host’s `TLS-SIGALG` support. “Dual-host” in this document means the two Tongsuo hosts used at the time; it does not mean other versions have been verified.
- **Platform marks**: 🟢 mac means the parameter passed dual-host EVP on the mac snapshot module; 🟢 linux-x86_64 means it passed Linux x86_64 / Tongsuo EVP in this round; ⚪ means the platform is not integrated or was not verified in this round. TLS status is listed separately; skips and timeouts do not count as passes.

### linux-x86_64

- **OS**: Ubuntu 24.04 x86_64.
- **Compiler**: Ubuntu Clang 18 (`cc`); the system also has GCC 13.3. This round did not modify submitted source and did not newly install quadmath.
- **Provider build configuration**: target `linux-x86_64`, `./config linux-x86_64 OPENSSL_PREFIX=... --with-gmp-source=...`, 220/220 instances. Parameters that depend on `rdtsc` / `x86intrin.h` are enabled by default only on this target.
- **Test host**: Tongsuo. This round only smoke-tested the newly integrated 12 parameter sets; the original 208 were not fully retested on Linux.
- **Outer adaptation**: does not modify submitted source under `ngcc/candidates/**`. On Linux Clang, Amoeba inlines C99 `inline` via `-O3` in `make/schemes/kem-02.mk` (Darwin already had equivalent handling in `make/ref.mk`). sign-07 uses `make/compat/sign-07/NTT.h` to override include order and hide the unused `MultiplyNTT` declaration.
- **Platform marks**: EVP passed for all 12 newly integrated parameter sets. TLS/certificates passed for 8 KEMs and CS-128/256; the UVW-128/256 certificate path did not return within 1800 seconds at the CSR stage and is not counted as a pass.

## Table notes

- **Sort order**: parameter sets of the same scheme are ordered from lower to higher security category; within a category the original parameter order is kept.
- **TLS marks**: “✓” means dual-host TLS 1.3 functional tests passed on the current module; “—” means the capability is registered but this round’s tests were skipped; “✗” means the corresponding capability is not registered (see Notes). Registration is not the same as a passing test.
- **Call names**: lists the primary EVP name and the registered TLS `group` / `sigalg` names; both use a unified naming scheme. Numeric UUID OID aliases for signatures are in the [OID registry](ngcc/metadata/sig-oids.json). See Usage for how to call them.
- **Source update time**: taken from HTTP `Last-Modified`, a pinned Git commit time, or the date of the proposal team’s attachment post; the date link points to the corresponding record. HTTP file times and post dates are not necessarily the source-version release date. Records for HARE, Mithril, TRIKE, and Octarine contain no confirmable update time and are marked “unconfirmed”.
- **Sizes**: unit is bytes **B**. Public keys are the proposal API’s raw encoding, without SPKI/X.509 wrapping. Sizes of integrated signatures are one measured length retained in the size registry. Each entry’s `size_evidence` and `size_evidence_module_sha256` identify the sample log and module; this round’s sizes come from the current module’s Tongsuo EVP logs. One measurement is not a mean or a maximum. Unintegrated parameters use source-declared or publicly stated nominal values; provenance is in Notes when the parameter is not integrated.
- **Timing**: records wall-clock time of complete test cases. EVP cases include key generation and multiple algorithm operations; signature TLS cases include encoding/decoding, CSR, certificate issuance, chain verification, and handshake. Timing includes process startup and runtime overhead; tests may run concurrently and must not be treated as a performance metric for a single algorithm or handshake. Parameter sets whose historical full-case time exceeded 1 second are skipped by default; table status comes from the listed test snapshots, and later skip-list changes do not rewrite completed results.
- **Notes**: filled only for a real test problem, failure, timeout, skip, platform limitation, or a parameter set that is not integrated / not included in testing. Fully integrated rows with no such issue leave this cell empty. Public reports that were not reproduced on the listed modules are omitted here; they are cited separately and are not a functional-availability mark. Scheme names link to the official NGCC proposal pages.
- **TLS configuration**: TLS capabilities use private code points; both peers must use a consistent mapping. Certificate issuance, certificate verification, and TLS handshake are tested separately.
- **Protocol length bounds**: public keys of 7 integrated KEMs exceed the 16-bit `key_share` length bound. Measured signatures of QingLuan-256 and Sigurd-256 exceed the 65,535 B `CertificateVerify.signature` limit, but certificate issuance and verification tests passed. The integrated EVP signature parameter UVW-256 has a raw public key that exceeds the 24-bit length limit of a single certificate and does not register TLS-SIGALG. Format definitions: [RFC 8446 §4.2.8](https://www.rfc-editor.org/rfc/rfc8446.html#section-4.2.8), [§4.4.2](https://www.rfc-editor.org/rfc/rfc8446.html#section-4.4.2), [§4.4.3](https://www.rfc-editor.org/rfc/rfc8446.html#section-4.4.3). Usable `key_share` space also depends on overhead from vectors, extensions, and other ClientHello fields.

## Maintenance notes

Submitted reference implementations remain byte-identical: do not modify or in-place patch `ngcc/candidates/**`. Allowed work is limited to outer adaptation (`make/schemes/*.mk`, CFLAGS, `make/compat/` include overrides, shims, provider glue, metadata, documentation). If a problem can be solved only by changing the author’s `.c/.h`, that parameter set stays excluded, with the reason recorded in `integration-policy.json`.

After updating sources, parameters, names, or modules, check reports per the test policy and sync this document; unrun items stay “skipped”. Re-run slow parameters only during an explicit full test.
