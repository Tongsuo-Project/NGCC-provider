BIKE_MLThre v2
==============

This directory is a cleaned submission package for the BIKE_MLThre KEM
implementation and the API_PKC KEM KAT test driver.

Contents
--------

- Core BIKE KEM implementation: top-level `*.c` and `*.h` files.
- NIST-style deterministic RNG used by BIKE: `FromNIST/rng.c` and
  `FromNIST/rng.h`.
- Unmodified API_PKC evaluation hash/XOF functions: `auxfunc.c` and
  `auxfunc.h`.
- Streaming adapter for API_PKC `pseudoXOF`: `xof_prng.c` and `xof_prng.h`.
- Generated MLThre model used at runtime: `mlthre_model.c` and
  `mlthre_model.h`.
- API_PKC KEM KAT driver and adapter: `kat/`.
- Build and test entry point: `Makefile`.

The BIKE KEM API exposed by this implementation is:

- `crypto_kem_keypair(pk, sk)`
- `crypto_kem_enc(ct, ss, pk)`
- `crypto_kem_dec(ss, ct, sk)`

Requirements
------------

To build and run the KAT test program, the system needs:

- A C99 compiler, tested with `gcc`.
- `make` and `ar`.
- OpenSSL development headers and library, because `FromNIST/rng.c` uses
  OpenSSL AES through `libcrypto`.
- The standard math library, linked as `-lm`.

On Debian/Ubuntu systems, the OpenSSL dependency is usually provided by
`libssl-dev`.

Reproducibility and C99 Scope
-----------------------------

This package is built and tested in C99 compilation mode:

```
make kat128
make kat256
make kat512
```

The current Makefile passes `-std=c99` to the compiler, and the 128-bit,
256-bit, and 512-bit KAT runs have been verified with GCC on Linux x86_64.
The legacy 192-bit compatibility target also passes its KAT, but no 192-bit
reference vector is included in this package.

This should be described as "requires a C99-compatible compiler" or "tested
with GCC using `-std=c99`". It should not be described as a pure ISO C99
portable implementation. The code still depends on the normal project build
environment, including OpenSSL/libcrypto and platform/compiler support used by
the BIKE implementation.

KAT Test
--------

Run the API_PKC KEM KAT test for each supported parameter set from this
directory:

```
make kat128
make kat256
make kat512
```

Each target first cleans generated objects, rebuilds `libbike_v2.a` with the
matching security macro, builds the matching KAT executable, and runs it.

Generated executables:

- `kat_bike_kem_128`
- `kat_bike_kem_256`
- `kat_bike_kem_512`

Generated KAT output files:

- `output/KAT_KEM_BIKE_v2_128.txt`
- `output/KAT_KEM_BIKE_v2_256.txt`
- `output/KAT_KEM_BIKE_v2_512.txt`

Verified reference vectors are also included in `test_vectors/`:

- `test_vectors/KAT_KEM_BIKE_v2_128.txt`
- `test_vectors/KAT_KEM_BIKE_v2_256.txt`
- `test_vectors/KAT_KEM_BIKE_v2_512.txt`

These files are provided for reproducibility and result comparison. They are
not required as input to the KAT program; running `make kat128`, `make kat256`,
or `make kat512` regenerates the corresponding output file under `output/`.
The reference vectors use the API_PKC auxiliary hash/XOF profile described
below; they do not match vectors generated with the original SHA3/SHAKE
primitives.

The KAT driver performs 10 deterministic test cases. For each case it runs
key generation, encapsulation, and decapsulation, then compares the
encapsulated and decapsulated shared secrets. A successful run exits with code
0.

Expected Lengths
----------------

For the verified parameter sets, the KAT output lengths are:

| Parameter set | PK_Len | SK_Len | CT_Len | SS_Len |
| --- | ---: | ---: | ---: | ---: |
| BIKE_v2_128 | 1541 | 3114 | 1573 | 32 |
| BIKE_v2_256 | 5122 | 10276 | 5154 | 32 |
| BIKE_v2_512 | 18751 | 37566 | 18815 | 64 |

Build Only
----------

Build just the static library for one parameter set:

```
make clean
make SECURITY=128

make clean
make SECURITY=256

make clean
make SECURITY=512
```

The resulting library is `libbike_v2.a`.
Intermediate objects and parameter-specific archives are isolated under
`.build/<SECURITY>/`, so changing `SECURITY` cannot reuse incompatible objects.

Clean
-----

Remove generated objects, libraries, and KAT executables:

```
make clean
```

Remove generated KAT output as well:

```
make distclean
```

Notes
-----

- `kat/KEM_AlgorithmInstance.c` adapts the API_PKC KEM interface to BIKE's
  `crypto_kem_*` functions.
- `auxfunc.c` and `auxfunc.h` are byte-for-byte copies of the API_PKC supplied
  files and must not be modified.
- BIKE's 256-bit hash outputs use API_PKC `sm3hash`; 512-bit hash outputs use
  API_PKC `pseudohash`.
- Sparse-vector sampling uses API_PKC `pseudoXOF`. `xof_prng.c` generates one
  complete XOF stream per seed and exposes sequential reads, preventing repeated
  use of the same XOF prefix. In key generation, `h0` and `h1` consume
  consecutive portions of the stream.
- The KAT seed is generated by the API_PKC SM3 DRNG. The adapter derives BIKE's
  NIST-style `randombytes()` state from that seed before key generation and
  encapsulation, making the test output deterministic.
- API_PKC documents `pseudohash` and `pseudoXOF` as correctness and preliminary
  performance evaluation functions, not production-security primitives. This
  package is therefore an API_PKC evaluation profile of BIKE.
- BIKE is a KEM. The API_PKC SIG and KEX KAT drivers are not part of this
  package.
